The done-claim template G10 enforcement

Every "task complete" / "shipped" / "done" message I post will follow this shape. Five lines, mandatory.

✅ Done — <feature name>
PR:       <gh-url>
Bundle:   <before-hash> → <after-hash>
Smoke:    <screenshot / curl output / scenario>
Truth:    IMPLEMENTATION_STATUS <commit-sha>
Gates:    G0 G1 G2 G3 G4 G5 [G6] G7 [G8] G9 G10  # brackets = N/A
If I post a done-claim missing any of these five lines, treat it as untrusted. Tell me to re-verify. Don't accept "should work" or "I tested it" without evidence.

Adoption protocol how this becomes real

What Nova does, starting immediately

  1. Every PR I open gets the PR_CHECKLIST.md block in the body, with gates checked-off as I verify them.
  2. Every "done" claim follows the G10 template — five lines, mandatory. If I can't produce one of the lines, the task isn't done.
  3. Every drift signal I detect mid-task gets surfaced before I keep going — pause, run the response, then resume.
  4. No memory entry without a Why: and How to apply: line.
  5. No "X is built" claim without file:line evidence cited in the same message.

What Kim does (zero overhead)

  1. If a done-claim arrives missing any of the 5 G10 lines, reply where's the evidence? — I'll produce it or retract.
  2. If you spot a new drift pattern, say that's a drift signal — I'll codify it.
  3. This file (and the 3 markdown sources) supersede any conflicting memory entry until Kim updates them.
