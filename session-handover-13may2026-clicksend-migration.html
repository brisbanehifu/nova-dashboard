1. Friday 15 May overlap (PR #435) DEPLOYED + VERIFIED

Kim flagged overlapping bookings on Brisbane HIFU's Friday 15 May agenda (Ali Bull 1:00-2:00 pm + Johana Serrano 1:30-2:00 pm on same staff). 6. P0 outage — master api_username silently reformatted RESOLVED IN ~5 MIN

The moment the Redlandshifu sub-account was saved, ClickSend reformatted the master subaccount's api_username from Brisbane.HIFU.clinic@gmail.com (email-as-username) to BrisbaneHifu (short label).

BAT's Railway env var CLICKSEND_USERNAME still held the old email → every SMS API call started returning 401 Unauthorized. Brisbane HIFU SMS sending was down until fixed.

Fix sequence:

railway variables --set CLICKSEND_USERNAME=BrisbaneHifu --service web
railway redeploy --service web --yes
# wait ~30s for container restart
railway ssh --service web 'echo $CLICKSEND_USERNAME'  # → BrisbaneHifu
# API auth check returns 200 OK with balance $78.23

Rule banked: after any ClickSend account restructure, verify process.env.CLICKSEND_USERNAME matches the dashboard "Username" column. Sub-account creation can mutate the master's API username, especially on legacy email-as-username accounts. Diagnostic command for future P0:

railway ssh --service web 'cd /app && node -e "
const axios = require(\"axios\");
const auth = \"Basic \" + Buffer.from(process.env.CLICKSEND_USERNAME + \":\" + process.env.CLICKSEND_API_KEY).toString(\"base64\");
