What clients actually experienced (root cause investigation)

Polly (Vodafone) + Chris (Telstra) + Rosalind all reported not receiving SMSes. Investigation revealed:

  • ClickSend Smart Sender was set to "Shared Numbers" (only option — no alpha tag registered) → 27% of last-14-day sends came from random rotating AU mobile numbers
  • Telstra/Vodafone silently filter unregistered numeric senders even when ClickSend's DLR reports "delivered to network"
  • Our notification_logs.status='sent' was misleading — only meant HTTP 200 at submit, NOT carrier-confirmed delivery. ✅ Send-side closed by PR #438 today — row now carries provider_message_id + per-recipient provider_status
  • ClickSend's status_text="Message delivered to the handset" is misleading default 201 description, NOT actual DLR. ✅ Captured verbatim in provider_status_text column now — visible at log-row level so we don't confuse it with delivery again
  • Real DLR moves the status badge from Sent → Delivered. Polly's and Chris's messages sat at Sent forever. ⏳ DLR-side closure is the follow-up PR — delivered_at/failed_at columns reserved, webhook handler to come
